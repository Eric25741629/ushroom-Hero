# 寶兒／暴哥萬神專用模式設計

日期：2026-07-15

## 目標

為 `web-001`（寶兒）與 `web-002`（暴哥）加入獨立於一般日常腳本的「萬神專用模式」。這兩個帳號平時只需開啟 Web H5 頁面刷小怪；只有使用者在中控板啟用萬神專用模式後，排程才會於指定時間執行萬神試煉。

第一版以每週成功跑滿 10 局作為完成條件。5000 週積分判定不在本版範圍，後續取得可靠積分來源後再替換完成條件。所有排程時間均使用台灣時間（Asia/Taipei）。

## 使用者體驗

### 帳號卡片

`special_wanshen_account=true` 的帳號卡片保留原本「開啟網頁掛機（不跑任何腳本，僅刷小怪用）」按鈕，並在其旁新增小型狀態按鈕：

- 未啟用：`× 跑萬神試煉・未啟用`，使用中性色背景。
- 已啟用：`✓ 跑萬神試煉・已啟用`，使用綠色背景。
- 本週完成：`✓ 本週已完成，不再執行`，使用完成色背景。

點擊未啟用按鈕會啟用模式；再次點擊已啟用按鈕會取消模式。狀態必須保存到 `bot_config.json`，控制程式重啟後仍維持原狀。

### 任務快捷區

寶兒與暴哥的任務快捷區只顯示「萬神試煉」，不顯示商店購買、地獄之門、坐騎衝刺、家族任務、挖礦、每日任務、菇菇武道會、農場種植、農場買種、龍骸聖域等一般任務。

其他裝置維持目前的任務快捷區與按鈕行為。

## 設定模型

每台特殊帳號新增以下裝置設定：

```json
{
  "special_wanshen_account": true,
  "special_wanshen_enabled": false,
  "special_wanshen_rounds": 10
}
```

- `special_wanshen_account`：標記此裝置使用專用流程；預設為 `false`，只有寶兒與暴哥設為 `true`。
- `special_wanshen_enabled`：中控板狀態按鈕控制的持久化開關；預設為 `false`。
- `special_wanshen_rounds`：第一版每週目標局數；預設與寶兒、暴哥實際設定皆為 `10`，沿用既有 `fight_test(d, rounds=...)` 的「一局＝打到第一次失敗後結算離場」定義。

專用模式不依賴 `enable_wanshen`、`enable_dungeon` 或 `enable_dungeon_manager`。只要裝置被標記為特殊帳號，一般 pipeline 就不得執行；`special_wanshen_enabled` 只決定萬神排程是否啟用。

## 執行隔離

特殊帳號的 runtime 流程在進入一般每日 pipeline 前先分流：

1. `special_wanshen_account=false`：維持既有完整 pipeline。
2. `special_wanshen_account=true` 且 `special_wanshen_enabled=false`：不執行任何腳本；Web H5 頁面可維持開啟刷小怪。
3. `special_wanshen_account=true` 且 `special_wanshen_enabled=true`：只檢查萬神專用排程，不呼叫一般 pipeline 的任何其他任務。

「開啟網頁掛機」對特殊帳號使用非腳本掛機語意：它只確保頁面存在，不得因此啟動一般 pipeline。萬神專用排程仍由裝置執行緒持有 Playwright 操作權，避免 Flask 執行緒跨執行緒操作 Playwright 物件。

前端對特殊帳號呼叫既有 `/api/web_launch/<ip>` 時傳入 `manual_hold_until_closed=false`。因此頁面可以長時間存在，是否執行腳本完全由專用 runtime 分流決定，不會被手動模式的 hold 永久擋住凌晨排程。

## 排程規則

採台北本地時間與 Python `weekday()`（週一為 0）：

- 有效星期：週二至週六，即 `weekday in {1, 2, 3, 4, 5}`。
- 有效時段：台灣時間 `03:00:00 <= now < 07:00:00`，即 `hour in {3, 4, 5, 6}`；其餘時間一律不執行。
- 同一日最多嘗試一次；開始執行前即寫入當日嘗試紀錄，避免有效時間窗內重入或程序錯誤後於下一個小時連續再打。
- 若 03:xx 沒有喚醒或當時未能開始，可在同一天 04:xx、05:xx 或 06:xx 的下一次喚醒補執行；07:00 後不補跑。
- 每週完成紀錄存在時，本週不再執行。
- 週二成功完成 10 局後，週三至週六跳過。
- 當天入場、進場、戰鬥或結算失敗，或未跑滿 10 局時不寫完成紀錄；下一個有效日 03:00–06:59 再重試。
- 週六仍失敗時，本週不再有後續有效日；下週二重新開始。

特殊模式使用兩個獨立紀錄鍵：`萬神專用_嘗試` 以日期限制每日一次，`萬神專用_完成` 以 ISO 週限制每週完成後不再執行。兩者都不共用一般 `萬神試煉` 紀錄，避免歷史紀錄或開關互相污染。

## 後端與狀態 API

新增 `GET/POST /api/special_wanshen/<ip>`，負責：

- 驗證裝置確實為 `special_wanshen_account=true`。
- 讀取與更新 `special_wanshen_enabled`。
- 透過既有 `config_manager.update_device_config` 保存到 `bot_config.json`，不重寫其他裝置設定。
- 回傳目前模式、目標局數、本週是否完成與下次有效嘗試時間。

`GET /api/special_wanshen/<ip>` 提供前端輪詢所需欄位：`account`、`enabled`、`rounds`、`attempted_today`、`completed_this_week` 與 `next_attempt_at`。前端點擊後可先做樂觀更新，但下一輪輪詢必須使用此端點的後端權威狀態校正，避免寫入失敗時按鈕顯示錯誤。

## 完成與失敗語意

萬神執行沿用 `battle.weekly_trials.fight_test`：

- 呼叫 `fight_test` 前先寫入當日嘗試紀錄，確保同日最多一次。
- 回傳 `True`：代表跑滿設定局數；寫入 `萬神專用_完成` 本週完成紀錄，前端顯示「本週已完成，不再執行」。
- 回傳 `False` 或拋出可處理例外：不寫完成紀錄，保留已啟用狀態；因當日嘗試紀錄已存在，只會在隔天有效時段重試。
- 使用者按下取消：立即將 `special_wanshen_enabled` 保存為 `false`；尚未開始的排程停止。已進入單次萬神流程時不做危險的跨執行緒硬中斷，於既有安全中斷點或本次流程返回後停止後續排程。

## 5000 積分後續擴充

第一版不讀取或推估萬神週積分，也不以固定局數假裝等同 5000 分。後續確認可靠的遊戲內週積分讀取方式後：

1. 新增 `special_wanshen_target_score=5000`。
2. 在每次執行前與每局結算後讀取權威積分。
3. 以 `score >= target_score` 取代「跑滿 10 局」的完成判定。
4. 前端完成文案改回「本週積分已達到，不再執行」，並顯示實際積分。

此擴充不得使用會踢掉目前 Web H5 session 的額外 WS 登入。

## 測試策略

採目標測試，不執行整包 pytest：

- 設定測試：新欄位預設值、型別正規化、更新時保留同裝置其他設定。
- 排程純函式測試：週二至週六 03:00–06:59 才 due；週一、週日、02:59 與 07:00 後不 due。
- 順延測試：週二失敗不記錄，週三可重試；週二成功後同週後續不 due。
- 執行隔離測試：特殊帳號不呼叫一般 daily pipeline，只可能呼叫萬神入口。
- 執行結果測試：跑滿 10 局才記錄；失敗或例外不記錄。
- API 測試：啟用、取消、非特殊帳號拒絕、狀態讀回。
- 模板測試：特殊帳號只顯示萬神快捷項；按鈕三種文案與 CSS 狀態存在；其他帳號不受影響。

驗證命令限定為新增／受影響的測試檔，以及修改 Python 檔案的 `python -m py_compile`。

## 非目標

- 本版不實作 5000 積分讀取。
- 本版不更改其他帳號原有萬神排程。
- 本版不新增獨立背景程序或第二個 Playwright 瀏覽器。
- 本版不重構無關的一般任務開關、Master／Worker 路由或 WS runner。
