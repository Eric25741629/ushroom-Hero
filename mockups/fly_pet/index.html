飛寵管理 UI · 三個方向

三個原型，挑一個最像你會用的

同一份需求（6 個痛點）做出三種不同取向的飛寵管理介面。先看下面三張卡片各自最適合誰、最強解掉哪個痛點，再用對照表逐項比較，點卡片裡的按鈕即可開啟原型實際操作。

1抓指定類別　可搜尋的單一種類精準篩選
2看到圖標　每隻可見頭像，設計主體
3過濾更細但更簡單　即時、一鍵、單一搜尋框
4300+ 隻流暢　視窗化、總數/篩選數、批次分解
5種類視圖開關　分組 ↔ 平鋪 一鍵切換
6手機自適應　不橫捲、觸控、篩選收抽屜

三個方向

點「開啟原型」用同資料夾的 .html 直接操作
A

密集戰情表

為「我有 300 隻、要快速管理與分解」的進階使用者設計。資訊密度最高、批次操作最順。

最強解掉
  • 3單一搜尋框同比對種類名＋詞條名，所有條件一鍵即時切換，零多步驟。
  • 1可搜尋的種類多選下拉，鎖定單一 config_id 精準隔離。
開啟原型 → version-a-ops-table.html
B

圖鑑卡片牆

為「想用看的、靠外觀辨識」的使用者設計，讓「圖標」需求發光。

最強解掉
  • 2圖標是卡片主角（64–72px 含品質色環/星級），辨識度最高。
  • 5平鋪 ↔ 依種類一鍵切換，種類藥丸單點即精準隔離。
開啟原型 → version-b-gallery.html
C

種類瀏覽器

直接打中「我要抓指定類別」。左側種類索引下鑽，類別導向最直覺。

最強解掉
  • 1左側「種類索引」一點即鎖定單一種類，可即時搜尋收斂清單。
  • 4唯一兩項規模/手機都過關：每組卡片視窗化＋增量載入。
開啟原型 → version-c-species-browser.html

註解與已知保留

  1. A痛點4（partial）：桌面已視窗化（312 筆僅渲染約 20–26 列），但 review 指出手機端是一次渲染全部 312 張重卡。refine 已用 content-visibility:auto 低成本緩解（不改 JS 渲染路徑），並修掉「篩選後留白空屏」的 high bug；本表沿用 review 的 partial 評級。
  2. B痛點4（partial）：平鋪視圖有 60/批無限捲動，但 review 標 scale_ok=false，因「依種類」群組視圖未視窗化。refine 已替群組視圖補上分批渲染並加 esc() 防 XSS；本表沿用 review 的 partial 評級（refine 後實質改善）。
  3. C痛點4（✓）：三版中唯一 review 給 scale_ok=true。refine 進一步加每組卡片上限＋增量 append，首屏卡片由 224 降到 95，是規模面最穩的版本。
  4. A痛點6（partial）：版面重排與抽屜達標，但部分觸控目標（chip 34px、icon-btn 30px、checkbox 24px）小於 40px。refine 已在 ≤760px 放大主要控件，桌面密度不變；本表沿用 review 評級。
  5. BC痛點6（✓）：review 給 mobile_ok=true（抽屜→bottom sheet、版面重排、viewport meta 齊備），少數小於 40px 的次要控件已於 refine 放大。
  6. 整體：三個檔案皆為單一離線 HTML，直接用瀏覽器開啟即可運作，無任何外部資源載入。所有 ◐/✓ 取自各版本 review 的 requirement_coverage.status；refine 階段的修正只縮小差距，未提升原始評級，故表格保守沿用 review 結果。
開啟方式：直接雙擊任一 .html，或用瀏覽器開啟本頁後點卡片按鈕（連結為相對路徑，需與三個原型放在同一資料夾）。手機測試請用同一個檔案，或透過區網開啟。
