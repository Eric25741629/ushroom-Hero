# PITFALLS 研究（菇勇者自動掛機）

## 1. 長時運行記憶體/資源洩漏
- 警訊：運行越久越慢、OCR 延遲上升、程序被系統回收。
- 預防：循環內資源釋放、定期健康重啟策略、監控 RSS/handle 數。
- 對應階段：穩定性基建階段。

## 2. 排程飢餓（低優先任務永遠不執行）
- 警訊：某些任務長期 pending，收益偏斜。
- 預防：age-based priority、最大等待時間保底、排程審計日誌。
- 對應階段：統一排程器階段。

## 3. 狀態漂移（UI 顯示與實際執行不一致）
- 警訊：面板顯示 Running 但裝置無動作。
- 預防：heartbeat + state revision + command ack timeout。
- 對應階段：控制平面整合階段。

## 4. OCR 誤判造成錯誤決策連鎖
- 警訊：同畫面重複進錯分支、點擊異常區域。
- 預防：多訊號驗證（OCR+模板+顏色區塊）、低信心回退路徑。
- 對應階段：感知與策略穩定化階段。

## 5. 跨主機裝置 ID 衝突
- 警訊：命令送錯設備、狀態互相覆蓋。
- 預防：device_id 命名規範（host_id/device_serial）、註冊去重。
- 對應階段：多主機協作階段。

## 6. 人工強制命令破壞狀態機
- 警訊：強制打斷後系統卡在中間狀態。
- 預防：手動命令也要經 transition guard；提供安全中斷點。
- 對應階段：即時操控分頁階段。

## 7. 過早大重構
- 警訊：新架構未穩定前，舊功能回歸大量失敗。
- 預防：採 strangler pattern，逐模組包裝替換，保持可回退。
- 對應階段：全程。
